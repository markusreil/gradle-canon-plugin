# 01 — CI: build main on every change, branches on every PR

Status: **in review** — no code until maintainer approves this plan.

## Goal

Every change verified automatically: `main` builds on every push, every PR branch builds with the
same gate contributors run locally. No more "green on my machine" as the only signal.

## Non-goals (explicitly deferred)

- Release automation or tagging in CI (manual release stays).
- Publishing from CI (needs coordinates + credentials; arrives with the chunk-3 checkpoint).
- CI for the linking suite beyond `check` (linking stays a manual/documented step until chunk 6
  wires the loop).

## Design

GitHub Actions, two workflows:

- `build-main.yml`: on push to `main`, run the full gate (CI has network: no `--offline`).
- `build-pr.yml`: on `pull_request`, same gate.
- Runners: `ubuntu-latest`, JDK 17 ( Temurin ), matching the repo toolchain.
- Keep it minimal: checkout, JDK setup, Gradle setup action (caching + configuration-cache aware),
  run gate. No matrix (single JDK, single OS) until a concrete need appears — strict over clever.

Java version note: repo targets JVM 17 toolchain and runs on 17; CI uses the same.

## Decisions proposed (confirm or overrule in review)

| # | Decision | Proposal | If you prefer otherwise |
|---|----------|----------|-------------------------|
| D1 | Workflows | Two files (push-main + PR), same gate command. Approved by review | One workflow with triggers |
| D2 | Gate command | `./gradlew check --rerun-tasks` (full, no cache shortcuts). Approved by review | Plain `check` |
| D3 | Scope | No matrix, no release, no publish. Approved by review | Broader from day one |

## Acceptance criteria

- [ ] AC1 — Push to `main` triggers a green build (verified by observing a real run).
- [ ] AC2 — A PR branch triggers the same gate (verified by observing a real run).
- [ ] AC3 — Workflow files live in-repo under `.github/workflows/`; no secrets required.

## Small steps (in order, each verifiable — one step, one commit after review)

1. **1.1 Workflows.** `.github/workflows/build-main.yml` + `build-pr.yml` per D1–D3. Verify: YAML
   parses (actionlint if available, else careful review) — real-run proof happens at merge.
2. **1.2 Live proof.** Push to a branch / open a PR, observe both runs green; merge. Verify: green
   runs linked in the landing report.

## Verification

- Two green runs observed (main + PR).
- Reviewer approval of D1–D3 counts as verification for the CI shape.
